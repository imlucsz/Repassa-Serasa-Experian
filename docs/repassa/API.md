# Shared API contract v0.1
Canonical draft `contracts/openapi.yaml` (OpenAPI 3.0.3). Paths relative to `/api/v1`. Coordinate changes with both agents; no unilateral drift. Authenticated endpoints use Bearer JWT; refresh/session cookie is HttpOnly and checked by backend. Public catalog only AVAILABLE items, staff stock separate. IDs UUID, timestamps UTC ISO-8601, enum strings as schema. JSON requests/responses camelCase. List `{items,page,pageSize,total}`. `ErrorResponse`: `{code,message,requestId,fieldErrors?}`; 400 validation, 401 unauthenticated, 403 forbidden (or 404 for hidden resource), 404 missing/inaccessible, 409 transition/availability conflict, 429 rate limit, 503 service unavailable. Avoid raw DB errors. Never expose password hash, digest, refresh token, donor PII, internal storage key to public. DTOs reject unexpected fields. Use no-store on private/auth responses.

## Endpoints overview
- `GET /health`, `POST /auth/register`, `POST /auth/login`, `POST /auth/refresh`, `POST /auth/logout`, `GET /me`, `PATCH /me`.
- `GET /institutions` public active pickup points; `GET /me/institutions` staff memberships.
- `GET /materials`, `GET /materials/{id}` public available catalog and detail; public unavailable details return 404, private history still accessible to owner/staff.
- `POST /uploads` optional photo multipart, returns uploadId; `POST /donations`, `GET /me/donations`, `POST /donations/{id}/cancel`.
- `POST /materials/{id}/reservations`, `GET /me/reservations`, `POST /reservations/{id}/cancel`.
- `GET /institutions/{institutionId}/dashboard`, `GET /institutions/{institutionId}/materials`, `POST /institutions/{institutionId}/materials/{id}/receive`, `POST /institutions/{institutionId}/materials/{id}/reject`, `POST /institutions/{institutionId}/pickups/confirm`.

Login/register return access token + user, set refresh cookie (register creates student/session). Refresh rotates cookie returns same response; logout revokes current family and clears cookie, 204. Staff registration not public. CSRF origin check: allow only configured same-origin UI for cookie mutations, require `X-Repassa-Request: 1` on all auth POSTs, JSON content type when a body is present, with same-origin policy; reject cross-origin, no broad CORS. Local proxy preserves safe origin/host configuration. Private student endpoints owner-check; staff memberships checked at each request. See SECURITY. Code is present only in own active reservation DTO, nullable otherwise; pickup output returns safe reservationId/materialId/status/completedAt, never student contact info. Institution address is demo public data.

## Integration gate
Contract specification is a baseline; implement backend and frontend against exact fields, then run generated Swagger comparison and fixture/live integration. Any added/removed endpoints or changed enum/status/error require shared review. If endpoint not ready, frontend displays explicit dev-only mock or unavailable state. No production mock fallback. Test `POST` errors including wrong tenant, concurrency, invalid/expired codes; document changes in DECISIONS. Actual Swagger output may use expanded validation constraints; review compatibility rather than byte equality.
