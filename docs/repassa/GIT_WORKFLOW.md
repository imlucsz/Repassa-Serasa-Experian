# Git, agents and quality gates
Owner approves architecture/scope and final merge/release. Agents allowed to create/switch branches in their own clone/worktree, fetch/pull, commit, push feature branch and open/update PR autonomously. Do not ask approval for routine operations. Do not push main, force push, delete branches, rewrite history, reset/clean user work, bypass hooks, change remote or credentials without approval. Avoid shared working directory between Codex/Devin. `git status --short --branch`, `git fetch origin`, `git switch -c feat/DEV-01-backend origin/main` (from clean clone); Codex uses `feat/UX-01-foundation`. Existing branch? inspect rather than recreate. Keep branches small; update from main via `git merge origin/main` on own branch, resolve only own files; use PR instead of merging each other's unreviewed code. Do not stash others' changes automatically. Add named paths; review staged diff; conventional commits with task ID. Use `git push -u origin <branch>`, later normal `git push`. Open PR base main; never auto-merge unless owner explicitly changes this policy and same checks/review apply.

Ownership: Codex `src`, root app config, `public`, frontend tests. Devin `backend`, backend tests. Contract `docs/repassa/contracts/openapi.yaml`, security/CI, root shared files and status shared; coordinate changes sequentially. Video protected by guard for new/modified/deleted files. Existing tracked references aren't automatically cleaned; if owner wants removal, separate reviewed exception/update guard in policy PR (do not bypass guard). Agents may suggest changes but cannot authorize own bypass.

## Activate local protections
PowerShell: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-agent-env.ps1`. Linux/Devin: `bash scripts/setup-agent-env.sh`. Both set local core.hooksPath `.githooks` only if absent or same; stop on different existing hook path; inspect and integrate intentionally. Shell hooks run via Git for Windows/Linux. `pre-commit` checks staged contents (not worktree) and `git diff --cached --check`. `pre-push` denies direct push/delete main, remote branch deletion, non-fast-forward, scans introduced commits (using remote tracking refs for new branches; fetch first). Local hooks are bypassable by users/tools; CI is independent but also needs branch protection. Heuristic scans changed text/path/size, not full secret history or binary content. Files over 10 MiB are blocked, `out`, references, media output, `node_modules`, build artefacts and real env files excluded. Existing unrelated historical files unchanged are not scanned. Do not make source modifications to guard to avoid failure.

Repository Settings → Rules → Rulesets (or Branches → protection) → target `main`; require PR, required status checks `agent-guard`, `frontend-quality`, `backend-quality`, one approving human review, dismiss stale approvals, require conversation resolution and up-to-date branch. Block force pushes and deletions; no agent bypass, apply to admins if appropriate. Protect CI/guards/doc critical changes with human review; code owners optional after actual collaborator handles confirmed. Do not invent accounts. Enable secret scanning/push protection if offered. No permissions change by this kit. CI uses `pull_request`, not `pull_request_target`, minimal read permissions, no production secrets. Branch rules must be configured in GitHub, not just YAML. Verify by opening PR and seeing exact check names, not merely assuming. Initial PR may expose baseline failures; fix real causes without weakening checks. ## PR review
What/why, task identifier, exact scope, acceptance outcomes, checks actual, screenshots/DB proof, contract changes, migration/rollback, known blockers, no secret/PII, no unsupported feature claims. Review other agent's integration interfaces without editing their branch unless requested. Merge small foundations first, then dependent PRs; integration branch only when needed. Release tag/demo deploy by owner after smoke test. See `.github/pull_request_template.md`.
