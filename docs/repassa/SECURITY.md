# Security, privacy and operational rules
Public repository: never commit real `.env`, bearer/refresh tokens, private keys, DB URLs with secrets, Supabase service-role key, passwords, personal data or license-restricted reference assets. Use safe placeholders in examples. `VITE_*` is public build-time configuration; no secret there. Never paste secrets into PR or logs. Use secret manager for approved environments and rotate exposed creds (do not rely on deleting commit). Existing tracked third-party reference MP4s need owner license review; do not delete/rewrite history autonomously.

## Authentication and authorization
Argon2id password hashing with vetted library and memory/time params measured on host (OWASP starting min 19 MiB, 2 iterations, parallelism 1); no plaintext. Normalize email, generic login failures, rate-limit login/register/refresh/pickup with trusted IP + account/scope as appropriate, account enumeration mitigation. Access JWT short (15 min proposed), validate issuer/audience/expiry/algorithm/key; store access in frontend memory only; refresh random >=256 bits hashed at rest, rotates, family revocable on logout/reuse, 7 days proposed. On concurrent refresh use client single-flight; server transaction prevents double rotation; define documented reuse behavior. Check active user and staff membership server-side on sensitive operations (never trust client or stale JWT role alone). No public role elevation. Seed/admin provisioning controlled; never seed production. Before real public registration add verification/reset/privacy/support.

Refresh cookie `HttpOnly`, `Secure` in HTTPS, `SameSite=Lax` or stricter, host-only, `Path=/api/v1/auth`, max age aligned; local insecure cookie only explicitly local HTTP. Access token never in cookie response logs/localStorage. Validate allowed `Origin` for cookie-auth mutations (reject missing origin for browser flow unless explicit safe test/server pathway); require `X-Repassa-Request: 1` on all auth POSTs (non-secret constant), JSON content type when a body is present, and validate Origin; no blanket credentialed CORS. Production same-origin proxy and cookie path must be verified. Clear cookie with matching attributes. Private/auth responses `Cache-Control: no-store`. Rate limit defaults proposal: login 5/min per IP+normalized identity and IP-wide cap, pickup 10/min per staff/institution and IP cap, uploads 10/min/user; tune demo, use DB/store-backed limits for multiple instances or declare single replica limitation. Trust forwarding only known proxy, IPv6 prefix normalization, don't use attacker-controlled X-Forwarded-For.

## Data isolation and uploads
Every resource ownership and membership check before return/mutation; test cross-tenant/list/pickup. Parameterized queries, DTO whitelist, size/pagination limits. Pickup code keyed digest, one-time, no logging; constant-time matching where relevant. No PII in URLs/status/errors. Photo only JPEG/PNG/WebP, magic bytes, 5 MiB, pixel dimension limits, strip EXIF by re-encode where feasible, random object key, no SVG/HTML, no arbitrary URL fetch (SSRF). Pending images private; public photo URL only for available item (short-lived signed URLs preferred). Track ownership before attachment, clean orphan uploads safely with retention; never delete unrelated objects. Supabase Storage server key not frontend; no public bucket for pending photos. Use synthetic images in demo if storage not yet ready and label mode; no fake functional upload.

## Operations
Request IDs and structured logs with redaction, no secrets or raw codes. TLS, security headers appropriate to SPA/API, restricted body limits, no debug stacks. DB migrations reviewed, backup, transactional tests. Dependency audit triage genuine risks, do not run `npm audit fix --force` blindly. GIT guard is heuristic, not a secret scanner guarantee; enable GitHub secret scanning/push protection if available, least privilege and protected main. CI untrusted PRs without deployment or production credentials; review workflow changes. Stop on destructive or billing changes; owner approval required. LGPD: academic demo only fictional data, minimal collection, no real student contact details, institution contacts public only with permission; production requires policy and retention/deletion workflow.
